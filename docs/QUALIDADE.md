# Qualidade — padrão ouro da Axon

Vale para todo módulo novo ou alterado da continuidade sem esforço (pedido do dono). Arquivo gordo (`server/store.ts`, `server/app.ts`, `server/mcp-tools.ts`, `src/Workspace.tsx`) só recebe ligação; a regra vai para módulo próprio.

## As três medidas

1. **Complexidade ciclomática ≤ 15 por função.** Com cobertura 100%, CRAP = complexidade, então este número é o CRAP.
2. **Cobertura 100%** de linhas, ramos, funções e instruções **dos módulos novos** (não do monólito).
3. **Mutação com 0 sobreviventes, só na fatia nova** (nunca o código inteiro). Mutante morto por tempo conta como morto. Mutante equivalente (que não muda comportamento nenhum) só se aceita documentado, nunca escondido com `ignore` ou ramo morto no código de produção.

## Os três comandos

Da raiz do projeto, depois de `npm install`:

```
# 1. complexidade (sai 1 se alguma função passar de 15)
npm run qualidade:complexidade -- server/store/artifact-hash-cache.ts

# 2. cobertura: <módulos> -- <testes> (sai 1 se qualquer medida ficar abaixo de 100)
npm run qualidade:cobertura -- server/store/artifact-hash-cache.ts -- tests/artifact-hash-cache.test.ts

# 3. mutação: um arquivo stryker.<apelido>.config.mjs por fatia
node ./node_modules/@stryker-mutator/core/bin/stryker.js run stryker.lembranca-do-hash.config.mjs
```

- **Mutação: use sempre o binário local** (acima). `npx stryker` solto resolve para um pacote legado.
- Nova fatia = novo `stryker.<apelido>.config.mjs`:
  ```js
  import { slice } from './stryker.common.mjs'
  export default slice({ name: '<apelido>', mutate: ['server/.../modulo.ts'], tests: ['tests/modulo.test.ts'] })
  ```
  `mutate` aceita faixa de linhas (`arquivo:início-fim`) para alteração dentro de arquivo antigo: só as linhas da tarefa.
- A mutação roda o executor `command`: um `tsx --test` por mutante, só nos testes da fatia (a Axon usa `node:test`, que o Stryker não conhece). Leva uns 2 minutos para ~80 mutantes. O Stryker copia o projeto para `.stryker-tmp/` (ignorado pelo git) e pula `.axon`, `output`, `dist`, `.claude`, `.env*` e bancos `*.sqlite*`.
- O TypeScript do projeto é o 7, que não tem a API JS de AST: por isso o medidor de complexidade usa `@babel/parser` e a configuração do Stryker aponta `tsconfigFile` para um arquivo que não existe (pula a reescrita do tsconfig, que usaria uma função que sumiu).

### Como o medidor de complexidade conta

`1 + if + ?: + && + || + ?? + case (não default) + for / for…of / for…in + while + do + catch`, mais as atribuições lógicas `&&=`, `||=`, `??=` (também são ramos). Cada função (declaração, expressão, seta, método) tem a sua conta; função aninhada não soma na de quem a contém.

### Cobertura com c8 + tsx

O c8 lê os mapas de código que o tsx já embute, então o relatório sai com o nome do `.ts` e com as linhas do `.ts` (conferido). Observação de 25/10/2026: numa execução em que nenhum teste chama uma função declarada no topo do arquivo, o c8 derruba a medida de **funções**, mas não lista as linhas dessa função como não cobertas. Por isso o corte exige as quatro medidas em 100, e a de funções fecha essa brecha. A causa não foi investigada.
